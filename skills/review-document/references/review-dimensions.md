# 评审维度检查清单

本文档定义各评审视角的详细检查项，供 subagent 评审时使用。

> **【铁律】本技能是纯评审操作。subagent 禁止修改任何文件、创建任何文件、实现任何代码。违反即作废。**

---

## 需求合理性审查

### 检查清单

- [ ] **功能目标清晰性** — 需求是否明确定义了要解决的问题？是否有一句话就能说清的业务目标？
- [ ] **需求逻辑一致性** — 需求内部是否存在矛盾？（比如 Step A 依赖的数据在 Step B 才生成）
- [ ] **与现有系统一致性** — 需求是否与现有模块的功能、接口、行为模式一致？有没有重复造轮子？
- [ ] **完整度** — 是否覆盖了所有关键场景？（正常流程、异常流程、边界条件）
- [ ] **合理性** — 需求是否在业务上合理？有没有不切实际的假设？（比如要求不存在的数据、违反业务流程的操作）
- [ ] **可验证性** — 完成标准是否明确？能否通过测试验证需求已满足？
- [ ] **依赖关系** — 是否清楚标注了前置依赖？（依赖其他存储过程、表、接口等）
- [ ] **范围控制** — 是否存在范围蔓延？需求是否过于宽泛或包含"未来考虑"的内容？

### 输出指引

只报告发现的问题。每个问题需说明：
1. 目标：需求到底想做什么
2. 缺陷：为什么当前描述不充分或不合理
3. 后果：如果不修复，可能造成什么影响
4. 建议：如何改进

## 设计完整性审查

### 检查清单

- [ ] **任务拆分粒度** — 实施计划的步骤拆分是否合理？每步是否可在 2-5 分钟内完成？
- [ ] **边界场景覆盖** — 是否覆盖了空值、重复值、超长值、不存在数据等边界情况？
- [ ] **错误处理路径** — 是否定义了各类错误场景的响应？失败时是否回滚/恢复？
- [ ] **变更范围** — 改动是否控制在合理范围内？是否无谓地触及了不相关的模块？
- [ ] **依赖关系顺序** — 任务之间的依赖关系是否合理？是否存在循环依赖？
- [ ] **接口一致性** — 定义的接口（入参、出参）是否与现有调用方保持一致？
- [ ] **数据完整性** — 数据操作是否考虑了并发、事务、唯一性约束？
- [ ] **回退方案** — 如果实施失败，是否有明确的回退策略？
- [ ] **安全考虑** — 是否考虑了权限校验、SQL 注入防护、敏感数据保护？
- [ ] **性能考虑** — 大数据量场景是否有性能考量？是否考虑了索引优化？

### PL/SQL 特有检查

- [ ] **单条查询异常处理** — 每条 `SELECT ... INTO` 是否被 `BEGIN EXCEPTION` 包裹？
- [ ] **事务边界** — `COMMIT`/`ROLLBACK` 的位置是否合理？是否有悬挂事务的风险？
- [ ] **返回码一致性** — 成功返回码是否使用 `'000#'` 格式？错误码是否包含可读的错误信息？

### 输出指引

针对设计文档，重点检查逻辑流是否有缺失步骤或分支。
针对实施计划，重点检查任务粒度是否可执行、依赖是否清晰。
不指出"代码风格"类问题（那是 PLSQL 规范审查的职责）。

## PLSQL规范审查

审查基准：`.claude/rules/plsql.md` + `.agents/skills/ddl-template/SKILL.md`

### 编译兼容性（阻断级）

- [ ] **Oracle 11g 兼容** — 不允许使用 `FETCH FIRST N ROWS ONLY`，必须使用 `ROWNUM <= N`
- [ ] **语法正确性** — 所有 DDL/DML 语句在 Oracle 11g 下语法正确

### 禁止语法（严重级）

- [ ] **GOTO 检查** — 任何场景均不允许 `GOTO` 语句
- [ ] **游标检查** — 禁止显式游标声明（`CURSOR cursor_name IS`），必须使用 `FOR` 循环
- [ ] **动态 SQL 注入风险** — 动态 SQL 必须使用绑定变量，禁止字符串拼接

### 空值判断规范

| 字段类型 | 正确判断方式 |
|----------|-------------|
| 文本字段 | `NVL(V_FIELD,'*')='*'` |
| 数量字段 | `NVL(V_QTY,0)<=0` |
| LOTATT/TRACEID | 必须使用 `NVL(字段,'*')='*'` |

### 异常处理规范

- [ ] 单条 `SELECT ... INTO` 必须有 `BEGIN EXCEPTION` 包裹
- [ ] `EXCEPTION` 块必须处理 `NO_DATA_FOUND` 和 `TOO_MANY_ROWS`
- [ ] `WHEN OTHERS` 必须包含 `SQLERRM` 和 `ROLLBACK`

### 命名规范

- [ ] 存储过程命名：`SPUDF_` 或 `PLS_` 前缀
- [ ] 入参：`IN_*` 前缀
- [ ] 出参：`OUT_*` 前缀
- [ ] 局部变量：`V_*` 前缀
- [ ] 循环变量：`ITEM`（而非其他命名）

### 变量声明规范

- [ ] `VARCHAR2` 必须指定长度（使用 CHAR 语义）
- [ ] 数量字段使用 `NUMBER(18,8)`
- [ ] 时间戳使用 `TIMESTAMP WITH TIME ZONE` 或 `DATE`

### 批量处理规范

- [ ] 批量数据处理使用 `FOR` 循环结构
- [ ] 大数据量操作使用 `BULK COLLECT + FORALL`

### 输出格式

对于每个发现的问题，使用以下格式：

```
检查项: [检查点名称]
严重程度: [阻断/严重/重要]
位置: [代码位置或文档章节]
问题: [问题描述]
规范依据: [引用的规范原文]
建议: [修复建议]
```

## Oracle代码审查

审查基准：`.claude/agents/oracle-reviewer.md`，调用 `oracle-reviewer` agent 执行。

### oracle-reviewer 调用方式

将文档中涉及 PL/SQL 代码的部分，以及相关规范文件，传递给 oracle-reviewer agent。

oracle-reviewer 会执行以下检查：

### Step 1: 编译兼容性检查（阻断级）
- Oracle 11g 语法兼容性
- 无 `FETCH FIRST N ROWS ONLY`

### Step 2: 禁止语法检查（严重）
- 无 `GOTO`
- 无游标声明
- 单条查询有 EXCEPTION 处理

### Step 3: 代码质量审查（关键）
- 空值判断是否符合规范
- 异常处理完整性
- SQL 注入风险（动态 SQL 是否使用绑定变量）

### Step 4: 性能审查（高）
- WHERE/JOIN 列索引检查
- 全表扫描检查
- 大数据量批量处理

### 输出格式

使用 oracle-reviewer 的标准报告格式（表格形式），包括：
- 检查项、状态、说明
- 问题列表（行号、严重程度、问题描述、修复建议）
- 总体评估（可部署/需修改后部署/禁止部署）

### 注意

- Oracle 审查员的输出直接包含在最终汇总报告中
- 不需要对 Oracle 审查员的结论做二次判断
- 如果 oracle-reviewer 返回"禁止部署"的结论，在汇总报告中标记为阻断级
